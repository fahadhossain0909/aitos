# AITOS World Intelligence — Implementation Foundation

## Status

This change introduces the first executable, dependency-light foundation. It does not claim all provider integrations, predictive models, or trading-policy wiring are complete.

## Safety boundary

- External intelligence is advisory evidence, never an order source.
- Unverified, single-source, disputed, retracted, stale, future-dated, or invalid observations cannot create directional impact.
- Missing asset/event beta defaults to zero; cross-asset relationships are never invented.
- Impact values are bounded research features, not calibrated return forecasts.
- The governor emits recommendations only. It cannot mutate core risk limits, sizing, stops, execution, or credentials.
- Intelligence outages leave the existing market-data and trading path unchanged.

## Contracts

SourceEvidence captures source provenance, source reliability, primary-source status, publication time, and first-seen time. IntelligenceEvent provides a versioned canonical record with bounded sentiment, severity, novelty, and confidence. The deduplication key identifies source-story duplicates; it does not imply syndicated copies are independent confirmations.

## Impact model

estimate_asset_impact applies signed sentiment, severity, novelty, model confidence, source reliability, verification status, a supplied point-in-time asset beta, and exponential half-life decay. The default beta is zero. Production betas must be estimated from point-in-time event studies and validated out of sample before use.

## Implemented durable ingestion slice

- A point-in-time asset snapshot aggregates verified event evidence, beta estimates, attention, horizon-specific impact features and advisory risk assessment. It filters both event observations and beta estimates by the snapshot as-of timestamp.
- A point-in-time event-study beta estimator filters by asset/event/horizon and requires the forward outcome to have become observable before the as-of timestamp. It defaults to zero below the minimum sample count, shrinks estimates toward zero, and bounds output.
- A source-verification gate uses operator-maintained publisher groups, freshness, reliability and explicit primary-source metadata. Multiple feeds from the same publisher count once; disputed/retracted observations fail closed. This is provenance verification, not independent factual adjudication.
- An explainable English financial-headline lexicon emits bounded sentiment, coarse event type/severity, matched terms, and a deliberately capped heuristic confidence (0.55). It is annotation-only, does not verify claims, and is not a multilingual trained NLP model.
- A bounded RSS/Atom adapter supports conditional ETag/Last-Modified requests, HTTPS host allowlists (including redirects), response-size limits, and DTD/entity rejection. It emits neutral, unverified observations; it does not infer sentiment or facts.
- ClickHouse event evidence is stored append-only in `world_intelligence_events`, keyed by source plus deterministic source-story identity.
- Per-source opaque adapter cursors are stored in `world_intelligence_cursors`.
- Durable ingestion order is **append ClickHouse evidence → publish normalized Redis event → save cursor**. A failed insert or publish leaves the cursor unchanged, so the source page is replayed rather than lost.
- This is at-least-once delivery, not a distributed transaction. The optional runner acquires one renewable Redis lease per source. Each lease receives a monotonic fencing token; ClickHouse cursor reads select the highest fencing generation, so a delayed old worker cannot supersede a newer checkpoint. Consumers must still use deterministic event identity because event publish is at-least-once. ReplacingMergeTree deduplication is eventual, so exact reads should use `FINAL` or an aggregation strategy.
- The store deliberately does not create a Redis consumer group or alter existing EventBus ACK/retry/DLQ policy. The runtime worker and production ClickHouse integration still need wiring and service-level verification.

## Not included in this foundation

No credentials are bundled, no scraping bypass or paid API dependency is introduced, and no LLM runtime, ClickHouse consumer group, autonomous strategy mutation, paper/live policy change, or automatic model promotion is introduced. The optional scanner hook is metadata-only and shadow-only. SEC contact identity and FRED API key are operator-supplied at runtime. GDELT is public but subject to its service availability and usage guidance. The RSS adapter is an opt-in library component and must be configured with an operator-approved feed URL and hostname allowlist. Those require provider-specific contracts, integration tests, and runtime evidence.


## Reliability, observability and attribution hardening

- RedisSourceLeaseManager uses atomic Lua scripts for exclusive lease acquisition, renewal and owner-checked release. Heartbeats mark the lease lost on Redis errors or ownership changes. A monotonically increasing Redis fence is attached to ClickHouse cursor checkpoints; cursor reads order by (fencing_token, updated_at), protecting the durable checkpoint from a delayed prior owner.
- Ingestion failures after a bounded provider page has been fetched are written to world_intelligence_dead_letters with the source, before/after cursor, normalized event payload, bounded error metadata and retry count. Replay is explicit, reuses the normal event identity, obtains the same distributed source lease and advances the checkpoint only after publish succeeds. Poll failures without a materialized page are not mislabeled as replayable DLQ items.
- The worker exposes process-local counters at /metrics and a health response at /health (default port 8120). Prometheus scrape configuration, alert rules and a Grafana dashboard are included under monitoring/. These counters reset on process restart; durable operational history remains in ClickHouse.
- Rejected-candidate markouts now retain WIATS event, narrative and source IDs. CandidateOutcomeStore.world_intelligence_attribution_report() aggregates counterfactual signed returns and missed/correct-rejection rates by those identifiers. The report explicitly labels the result observational, not causal; it is not used for strategy or risk decisions.
- The paper scanner remains shadow-only. The optional ingestion worker, lease system, replay and metrics endpoint do not grant order execution or model-promotion authority.


### Operator safeguards

- The Redis lease namespace defaults to aitos:wiats:lease; AITOS_WORLD_INTELLIGENCE_LEASE_TTL_MS defaults to 30000 and must be at least 3000. Lease/fence keys share a Redis Cluster hash slot. If Redis is unavailable, a source iteration is isolated and reported rather than terminating the whole poll loop.
- The ClickHouse dead-letter queue is capped at 1000 pending pages per source by default. Replayed/completed records expire after 90 days; pending records are retained until replayed or operator action. Error text is deliberately redacted to the exception class so provider URLs or credentials cannot leak into durable diagnostics.
- A replay compares the stored before/after cursor boundary with the current source cursor. If the cursor has moved to an unrelated value, replay leaves the record pending and raises an observable conflict instead of rewinding a newer checkpoint.
- The optional worker exposes health and Prometheus endpoints on port 8120. When using Prometheus/Grafana, enable both the observability and world-intelligence Compose profiles; the scrape target and alert rules are provisioned for the optional worker.
- Startup replay is disabled by default. Set AITOS_WORLD_INTELLIGENCE_REPLAY_DLQ_ON_START=true only after reviewing pending pages; the replay batch is bounded by AITOS_WORLD_INTELLIGENCE_REPLAY_DLQ_LIMIT (1–1000).
- The decision ledger also aggregates realized executed-trade net returns, win rate, fees and funding by the event/narrative/source IDs attached to accepted ENTRY decisions. The report is surfaced in the existing scanner decision-ledger health snapshot and remains observational, not causal.
- The worker writes append-only per-source run records to ClickHouse (180-day retention), including success/failure/lease contention, event counts, cursor boundaries, fencing generation and latency. The internal /sources endpoint exposes bounded 24-hour aggregates for operational inspection.
